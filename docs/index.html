このページで学べること

パソコンにアプリを入れるところから、変更を記録してGitHubに共有するところまでを一通り体験できます。後半では、チーム開発やアプリ自体の開発方法も紹介します。

01

まずは準備

インストールと準備

「やさしいGit」は、GitHubとつながるデスクトップアプリです。最初にアプリとGitHubアカウントを準備しましょう。

  1. 1

    アプリをダウンロード

    最新リリースを開き、お使いのOSに合ったファイルを選びます。Windowsはセットアップ版またはポータブル版、macOSはIntel / Apple Silicon用のDMG、LinuxはAppImage / debです。

  2. 2

    GitHubアカウントを用意

    アカウントがない場合は、GitHubでアカウントを作成します。アプリでログインすると、プロジェクトの共有やチーム招待を使えます。

  3. 3

    アプリを起動してログイン

    初回起動時にGitHubへのログインを案内します。連携に必要なGitHub CLIが見つからない場合は、アプリの案内に沿ってインストールしてください。Gitの基本操作はGitHub CLIなしでも使えます。

💡

配布ファイルはコード署名されていないため、OSが初回起動時に確認を表示することがあります。ダウンロード元が公式リリースページであることを確認してください。

02

最初の一歩

最初のプロジェクトを開く

起動したら、最初の画面から始め方を選びます。

✨

新しく作る

空のフォルダから始めます。フォルダを選び、必要なら言語やツールの.gitignoreテンプレートを追加します。

📂

既存フォルダを開く

すでにパソコンにあるプロジェクトを選びます。まだGit管理されていない場合は、アプリから始められます。

⬇️

GitHubから始める

自分やチームのプロジェクトを一覧から選んでダウンロードします。共有リンクから参加することもできます。

.gitignore は、ビルド成果物や一時ファイルなど、共有しなくてよいファイルを記録対象から外す設定です。

03

日々の作業

変更を記録して共有する

作業の基本は「変更を確認 → 記録 → アップロード」です。記録はパソコン上の保存、アップロードはGitHubへの共有です。

1編集するファイルを変更
→
2確認する「変更」画面
→
3記録するメモを付けて保存
→
4共有する「アップロード」
  1. ファイルを編集し、アプリの「変更」画面を開きます。
  2. 今回の記録に含めたいファイルを選び、何をしたか短いメモを書きます。
  3. 「変更を記録」を押します。記録はあとから履歴で確認できます。
  4. 「アップロード」を押すとGitHubに共有されます。初回はGitHub上のプロジェクト作成もアプリが案内します。
覚えておくこと

記録しただけでは、チームの人には届きません。共有するときはアップロードも行いましょう。「まとめて更新」では、仲間の新しい変更を取り込んでから通知も確認できます。

04

一緒に作ろう

チームで開発する

GitHub上のプロジェクトにメンバーを招待し、それぞれのパソコンで作業します。変更を小さく共有し、相談しながら本流へ取り込みます。

👩‍💻プロジェクトを用意作成者がGitHubに共有
→
📨仲間を招待「チーム」からユーザー名で招待
→
🧑‍💻各自で参加招待を承諾してダウンロード
  1. 作成者は「チーム」画面から相手のGitHubユーザー名を入力して招待します。招待には相手の承諾が必要です。
  2. 招待された人は「招待を確認」から参加し、プロジェクトをダウンロードします。
  3. 作業前に「まとめて更新」を押し、GitHub上の最新の変更を取り込みます。
  4. 変更ごとに作業の分岐を作り、作業後に記録・アップロードします。変更の提案を使って内容を相談してから本流へ取り込みます。
🤝

同じファイルの同じ場所を同時に編集すると、変更の合流時に調整が必要になることがあります。作業前にタスクを分け、担当や対象ファイルを共有しておくと進めやすくなります。

05

安全に試す

作業を分けて変更を提案する

作業の分岐（ブランチ）は、本流を保ったまま別の作業を進めるための作業場所です。機能追加や修正ごとに分けると、変更を見直しやすくなります。

変更の提案 →
  1. 「作業の分岐」画面で新しい分岐を作り、分かりやすい名前を付けます。例：feature/profile-page。
  2. その分岐に切り替えて作業します。作業中の変更は記録してから切り替えると安心です。
  3. 変更を記録し、アップロードします。
  4. アプリから変更の提案（Pull Request）を作成します。GitHub上で差分を確認し、チームの人にレビューを依頼できます。
  5. 確認が終わったらGitHub上で取り込みます。アプリで「まとめて更新」を実行して、手元の本流を最新にします。
変更がぶつかった（競合した）ときは？

同じ場所に複数の変更があると、Gitがどちらを残すか判断できず競合になります。ファイルを開き、残したい内容を相談して整理してから、解決したファイルを記録し直してください。内容が分からないまま強制アップロードで上書きしないでください。

06

チームのルールをそろえる

GitFlowを使う

GitFlowは、機能追加・リリース準備・緊急修正で作業の分岐を使い分ける進め方です。チームのリリース手順が決まっている場合に使います。

機能を作る

developから作業を始め、終わったらdevelopへ取り込みます。

リリース準備

公開前の調整を行い、本番用とdevelopの両方へ取り込みます。

緊急修正

本番用の分岐から修正し、本番用とdevelopの両方へ取り込みます。

「作業の分岐」画面の「GitFlowを初期化」から本番用の分岐を選びます。初期化後は、目的に合う開始操作を選んでください。チーム全員が同じ運用ルールを理解してから使い始めましょう。

07

やることを見える化

タスクを管理する

「タスク」画面ではGitHubの課題（Issue）を「未着手」「進行中」「完了」に分けて整理できます。緊急度や担当者を使って、次に取り組むことを見つけましょう。

  • タイトル、内容、担当者、ラベルを付ける
  • 緊急度や更新日などで並び替える
  • 進行中にすると、タスク名をもとに作業用の分岐を作る
  • 作業の提案やコメントをGitHub上で確認する

タスクを始める前に「何ができたら完了か」を短く書くと、チームで認識を合わせやすくなります。

08

大切なデータを守る

安全に使うために

🔐

秘密情報を共有しない

パスワード、APIキー、秘密鍵などをプロジェクトに入れないでください。アップロード前の安全チェックも確認します。

🌍

公開範囲を確認

公開リポジトリに送った内容は誰でも見られます。非公開でも招待したメンバーが見られるため、共有先を確認します。

🧹

不要なファイルを除く

.gitignoreを使い、設定ファイル、依存関係、ビルド成果物などを記録対象から外します。

⚠️

履歴にも残る

一度アップロードした情報は、あとでファイルを消しても履歴に残る場合があります。秘密情報を送ったときは、キーの無効化なども行います。

09

作る側に参加する

アプリを開発する

「やさしいGit」自体はElectronアプリです。ソースコードを取得し、Node.jsとGitがある環境で起動します。

git clone https://github.com/rumo-dev/yasashii-git.git
cd yasashii-git
npm install
npm start

開発の基本サイクル

  1. GitHubの課題やチームの相談から、作業内容を決めます。
  2. 最新の変更を取り込み、作業用の分岐を作ります。
  3. 小さな単位で実装し、動作を確認します。既存のテストはnpm testで実行できます。
  4. 変更を記録してGitHubにアップロードし、変更の提案を作ります。
  5. レビューで指摘を確認して修正し、合意できたら本流へ取り込みます。
配布版を作るとき

リリース時はpackage.jsonのバージョンに合わせたv付きタグをGitHubへ送ります。GitHub ActionsがWindows・macOS・Linux向けの配布ファイルを作ります。詳しい手順はREADMEを確認してください。

10

言葉を整理

よく出てくる言葉

Git
ファイルの変更を記録し、過去の状態をたどれる仕組み。
GitHub
Gitのプロジェクトをインターネット上に置き、共有するサービス。
記録 / commit
変更をひとまとまりとして保存すること。
アップロード / push
手元の記録をGitHubへ送ること。
取り込み / pull
GitHubにある新しい変更を手元へ持ってくること。
作業の分岐 / branch
本流に影響を与えず、別の作業を進める場所。
変更の提案 / Pull Request
変更を確認してもらい、本流へ取り込む相談をすること。
競合 / conflict
同じ場所に異なる変更があり、自分たちで整理する必要がある状態。
🌼

ひとりで悩まなくて大丈夫

困ったときは

エラーの詳しい内容を確認し、画面に表示された案内に沿ってください。不具合や改善案はアプリ内の「バグ報告・要望」から送れます。投稿はGitHub上で公開されるため、個人情報や秘密情報は書かないでください。

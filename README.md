# 🌱 やさしいGit

**Gitを、やさしい日本語で。** やさしいGitは、GitやGitHubを初めて使う人にもわかりやすい、Windows・macOS・Linux向けのデスクトップアプリです。

「commit」は「変更を記録」、「push」は「アップロード」のように、難しい用語を普段の言葉に置き換えています。必要に応じて、設定から元のGit用語を表示できます。

**次回リリース予定：v1.9.0** · [リリースとダウンロード](https://github.com/rumo-dev/yasashii-git/releases/latest)

## できること

- ファイルの変更を見比べて、必要なものだけ記録する
- GitHubにプロジェクトを作成・アップロードし、チームと共有する
- GitHub上のプロジェクトを一覧から検索してダウンロードする
- 作業の分岐を作成・切り替え、変更を合流する
- GitFlow用に本番用・開発用の分岐を準備する
- GitHubの課題をタスクとして管理し、緊急度・検索・並び替えを使う
- タスクを進行中にすると、タスク名の作業ブランチを作成する
- 履歴で記録者ごとの色を見分け、消えた記録から復旧用の分岐を作る
- 合流前の差分を確認し、変更の衝突を画面で解決する
- `.gitignore` を編集し、Node.js・Python・Unityなどのテンプレートを追加する
- リーフ・オーシャン・さくら・ミッドナイトなど、好みのテーマに切り替える
- プロジェクトを一覧から外す、またはPCのフォルダごと削除する
- 変更の提案、課題、チームの招待、お知らせをアプリ内で確認する
- GitHubアカウントを複数登録し、使用するアカウントを切り替える（GitHub CLI 2.40以降）

GitHubへのアップロード前には、パスワードやAPIキーなどの秘密情報や、大きなファイルが含まれていないか確認できます。

## ダウンロード

[最新リリースを開く](https://github.com/rumo-dev/yasashii-git/releases/latest) から、お使いのOSに合ったファイルをダウンロードしてください。

- **Windows**：セットアップ版、またはインストール不要のポータブル版
- **macOS**：Intel Mac用またはApple Silicon用の `.dmg`
- **Linux**：`.AppImage` または `.deb`

現在の配布ファイルはコード署名されていないため、WindowsやmacOSで初回起動時に確認画面が表示される場合があります。

## はじめ方

1. アプリを起動してGitHubにログインします。初回にGitHub CLIが必要な場合は、アプリが案内します。
2. 最初の画面から、既存フォルダを開く、新しいプロジェクトを作る、GitHubからダウンロードする、のいずれかを選びます。
3. 新しいプロジェクトを作るときは、必要に応じて `.gitignore` のテンプレートを選びます。あとから「設定」でも追加できます。
4. ファイルを編集し、「変更」画面で記録する内容を選んで変更を記録します。
5. 「アップロード」を押すと、初回はGitHub上にリポジトリを作成し、その後は変更を送ります。

GitとGitHub CLIが必要です。アプリ起動時にGitHubへログインします。GitHub CLIが見つからない場合は、インストール方法が案内されます。

## エディターとターミナル

上部の📝ボタンからプロジェクトをエディターで開けます。「設定」では自動検出、Visual Studio Code、Visual Studio Code Insiders、Cursor、OSの標準アプリを選べます。変更一覧でファイルを選ぶと、詳細欄や右クリックメニューからそのファイルをエディターで開けます。上部の⌨️ボタンは、プロジェクトのフォルダを作業場所にしてターミナルを開きます。

## タスク管理

「タスク」画面では、GitHubの課題（Issue）を「未着手」「進行中」「完了」に分けて管理できます。登録時に緊急度を設定し、タイトル・内容・担当者・ラベル・番号で検索できます。緊急度、更新日、作成日、名前、コメント数で並び替えられます。

進行中にするとタスク名から作業ブランチを作成して切り替えます。GitFlow初期化済みの場合はfeature・release・hotfixから種類を選び、完了時に対応する分岐へ取り込みます。作業中の変更がある場合は、名前を付けて一時退避できます。完了前にはサーバーの更新を確認し、取り込み先に更新がある場合は処理を止めて知らせます。

## GitHub Actions

「GitHub」画面の「Actions」タブから、手動実行・Node.jsテスト・Pythonテストのワークフローを作成できます。作成したファイルは `.github/workflows/` に保存されます。内容を確認してから「変更」画面で記録し、GitHubへアップロードしてください。GitHubに反映されたワークフローは、一覧から有効・一時停止を切り替えたり、手動実行・キャンセル・再実行したりできます。実行結果とログもアプリ内で確認できます。

ワークフローはGitHub上でコマンドを実行します。自動実行の条件や実行内容を確認してからアップロードしてください。手動実行するには、ワークフローに `workflow_dispatch` が必要です。入力項目がある場合は「項目名=値」を1行ずつ指定できます。

## GitFlow

「作業の分岐」画面の「GitFlowを初期化」から、本番用の分岐と開発用の `develop` を設定できます。`develop` がなければ本番用の分岐から作成し、すでに手元またはサーバーにある場合はそれを使います。初期化後は「機能を作る」「リリース準備」「緊急修正」から適切な元分岐を使って作業を始められます。作業用分岐の「GitFlowを完了」では、機能を `develop` に、リリースと緊急修正を本番用・開発用の両方に取り込みます。リリースと緊急修正ではバージョンの目印も作成します。

`feature/`、`release/`、`hotfix/` など、GitFlowで使う分岐名の接頭辞はこのプロジェクトのGit設定に保存され、分岐の開始・完了時にアプリが読み取って使います。完了前にはサーバーの更新を確認し、取り込み先に未取得の更新がある場合は処理を止めます。

初期化時に作業中の変更がある場合は、名前を付けて一時退避に保存します。退避した内容は初期化後も一時退避に残るため、必要に応じて「一時退避」画面から戻してください。

## 履歴と変更の確認

「履歴」画面ではGitHubにプロフィール画像がある記録者はその画像を表示し、ない場合は名前の頭文字を表示します。「記録者の色」から人ごとの色を設定すると、履歴の分岐図にも反映されます。メイン分岐の色は、記録者の色と重ならないよう自動で選ばれます。消えた記録は「消えた記録を探す」から選び、元の履歴を変更せず復旧用の分岐を作れます。

分岐を合流する前に、変更の概要とファイルごとの差分を確認できます。変更が衝突した場合は、共通の元の版・自分の版・取り込む側の版を見比べ、解決後の内容を保存できます。

## `.gitignore` テンプレート

プロジェクト作成時、または「設定」画面から、Node.js、Python、Visual Studio / .NET、Unity、Java、Rust、Go、Web、Windows、macOSのテンプレートを追加できます。既存の `.gitignore` は保持し、テンプレート内の未登録ルールだけを追記します。

## プロジェクトの削除

プロジェクト一覧の「削除」から、アプリの一覧だけから外すか、PC内のフォルダごと削除するかを選べます。フォルダごとの削除は、確認後に実行されます。

## バグ報告・要望

アプリ内の「バグ報告・要望」から、不具合の報告や機能の提案を投稿できます。投稿とコメントはGitHub上で公開されるため、パスワードや個人情報などを書かないでください。

## チュートリアルサイト

初心者向けの使い方、チーム開発の流れ、開発者向けの手順は [チュートリアルサイト](https://rumo-dev.github.io/yasashii-git/) をご覧ください。Astroで構築し、ページのソースは `src/`、静的ファイルは `public/` にあります。

GitHub Pages は `.github/workflows/pages.yml` から公開します。初回のみ、GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。その後 `main` ブランチのサイトソース、依存関係、公開ワークフローへの変更を push すると、自動でビルド・デプロイされます。Actions タブで「GitHub Pages に公開」の実行結果を確認できます。

サイトをローカルで編集・確認する場合は、`npm install` のあとに次のコマンドを使います。

```sh
npm run site:dev
npm run site:build
npm run site:preview
```

## 開発者向け

Node.js と Git をインストールした環境で、プロジェクトのフォルダから実行してください。

```sh
npm install
npm start
```

テストと配布用ビルド：

```sh
npm test
npm run dist:win
npm run dist:mac
npm run dist:linux
```

GitHub Actionsによるリリースビルドは、`package.json` のバージョンと同じ番号の `v` 付きタグをGitHubへ送ると開始します。

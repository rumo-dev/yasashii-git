# 🌱 やさしいGit

初心者にもわかりやすい、**すべて日本語**の Git / GitHub クライアント（Electron デスクトップアプリ）。
`commit` や `push` のような用語を、やさしい言い方に置き換えています。

| Git用語 | このアプリでは |
|---|---|
| commit | 変更を記録 |
| push | アップロード |
| pull | 最新を取り込む |
| fetch | 更新を確認 |
| clone | ダウンロードして始める |
| branch | 作業の分岐 |
| merge | 合流 |
| stage / add | 記録に含める |
| stash | 一時退避 |
| tag | 目印 |
| conflict | ぶつかり |
| revert | 取り消しの記録を作る |
| reset | ここまで巻き戻す |
| pull request | 変更の提案 |

設定で、元のGit用語を小さく併記する表示（学習用）の ON/OFF ができます。

## 使い方

| 目的 | Windows | Mac | コマンド |
|---|---|---|---|
| 起動する（初回は自動で準備） | `start.bat` をダブルクリック | `start.command` | `npm install` → `npm start` |
| インストーラーを作る | `build-installer.bat` | `build-installer.command` | `npm run dist` |
| テストする | `run-tests.bat` | — | `npm test` |

> Mac で `.command` が開けない場合は、右クリック →「開く」を選んでください。

## バグ報告・要望

アプリのスタート画面または左メニューの「バグ報告・要望」から、やさしいGitの投稿一覧を見て、不具合の報告・機能の要望・質問を投稿できます。投稿とコメントはGitHub上で公開されます。ブラウザで開いて続けることもできます。

## 配布する

`build-installer.bat`（または `npm run dist:win` / `dist:mac` / `dist:linux`）で `dist/` に次のファイルができます。

- **Windows**：`yasashii-git-Setup-1.0.0-x64.exe`（インストーラー）と、インストール不要の**ポータブル版** `yasashii-git-Portable-1.0.0-x64.exe`
- **Mac**：`yasashii-git-1.0.0-Mac-x64.dmg` / `-arm64.dmg`（Intel / Apple Silicon）
- **Linux**：`.AppImage` / `.deb`

各OS用のファイルは、そのOS上でビルドする必要があります。手元にない OS 向けは、
**GitHub に push して `v1.0.0` のようなタグをつける**と、`.github/workflows/release.yml` が
3 OS 分を自動でビルドして「Releases」ページに載せます（ダウンロードリンクをそのまま配れます）。

注意：コード署名をしていないため、初回起動時に Windows は「WindowsによってPCが保護されました」（→「詳細情報」→「実行」）、
Mac は「開発元を確認できません」（→右クリックで「開く」）と表示されます。広く配る場合は、署名証明書の用意を検討してください。
アイコンは `build/icon.png` / `build/icon.ico` を差し替えるだけで変更できます。

必要なもの：**Git**（必須）、**GitHub CLI `gh`**（GitHub連携を使う場合。https://cli.github.com/ ）

## GitHub ログインと「アップロード」（かんたん化）

- **起動するとまず GitHub へのログインが必要です。** ログインするまで他の画面には進めません（ブラウザの確認コード方式。うまくいかない場合はトークンでも可）。`gh` が未導入ならその場でインストールを案内します。
- **URL の登録は不要です。** 初めての「アップロード」を押すと、GitHub 上にリポジトリを自動で作成して接続し、そのまま送信します（日本語のフォルダ名は GitHub で使える名前に自動変換）。「変更」画面の **「記録して、そのままアップロード」** なら、記録から送信まで1ボタンです。
- **ダウンロードは一覧から選べます。** 自分の GitHub のプロジェクト一覧（絞り込み付き）から選ぶだけ。他人のプロジェクトは「URLを入力」からも可能です。
- **SourceTree など他のツールで取得したフォルダもそのまま開けます。** すでに接続先（origin）があればそのまま使え、SSH 形式（`git@github.com:…`）の場合は、ログイン中のアカウントで使える HTTPS 形式への切り替えを提案します。

### チームで使う（リンクで参加・招待）

左のメニューの **「チーム」** と、はじめの画面の **「リンクで参加」「招待を確認」** から使えます。

| やりたいこと | 操作 |
|---|---|
| チームの人に送られたリンクで始める | 「リンクで参加」にリンクを貼る（`/tree/…` つきや `git@github.com:…` 形式でもOK）。招待が届いていれば、そのまま参加してダウンロードします |
| まだ招待されていないとき | 「あなたのユーザー名」を表示するので、コピーして管理者に送り、招待してもらいます |
| 人を招待する | 「チーム」→「＋ 招待する」→ 相手のGitHubユーザー名と、できること（✏️編集できる／👀見るだけ／🛡️管理者）を選びます |
| 届いた招待に返事する | メニューのバッジ、または「招待を確認」から「参加する」「お断りする」 |
| チームにリンクを渡す | 「チーム」の「共有リンク」をコピー（招待メールが届かない人には「招待リンクをコピー」で直接送れます） |
| 一覧から選んで始める | 「ダウンロードして始める」には、自分のもののほか、招待された・所属チームのプロジェクトも「👥 チーム・共有」として並びます |

### 名前とメールの自動設定
ログイン直後と「変更を記録」の直前に、記録に残す名前とメールが未設定なら、ログイン中のGitHubアカウントから自動で設定します。
- 名前：GitHubの表示名（未設定ならユーザー名）
- メール：GitHub の非公開用アドレス（`<ID>+<ユーザー名>@users.noreply.github.com`）。本当のメールアドレスは公開されません
- すでに設定がある場合は**上書きしません**。「設定」画面の「GitHubアカウントから自動入力」でいつでも入れ直せます
- オフラインなどで取得できないときは、エラーで止めずに「設定」画面へ案内します

### 自動ひと言メモ
「変更」画面の「記録のメモ」に、変更したファイル名から下書きを自動で入れます。（例：`index.html と style.css を変更`、`a.txt を変更、b.css を追加`）
- 「記録に含めるファイル」を選んでいるときは、そのファイルだけが対象。選んでいなければ、すべての変更が対象
- 追加・削除・名前の変更も言い分けます。ファイルが多すぎるときは「◯個のファイルを更新（変更2・追加1）」にまとめます
- **自分で書いた（または消した）メモは、二度と自動で上書きしません。** 入れ直したいときは「✨ 変更したファイルから下書きを入れる」を押します

### リリースの生成
「GitHub」画面の **🚀 リリース** タブ（または「目印」画面の各目印の「🚀 リリースにする」）から、GitHub のリリースを1つの流れで作れます。
1. 「🚀 リリースを作る」を押す（まだ送っていない記録があれば、先にアップロードを提案）
2. **バージョン名**は、前の `v1.2.3` から次の候補（`v1.2.4`）を自動で入力。**リリースノート**は、前のバージョン以降の記録のメモから下書きを作成（自由に書き換え可）
3. 「リリースを作る」→ 目印をつけてGitHubへ送り、リリースを公開（「下書きとして保存」「先行版」も選べます）
- 既存のリリースの一覧（最新・下書き・先行版の印つき）と、ブラウザで開くボタンもあります
- すでにあるバージョン名はやさしい日本語で止めます。空白や先頭の `-` は使えません
- 目印（タグ）をきっかけにインストーラーを自動で作る設定（このアプリの `.github/workflows/release.yml` と同じ）なら、ここからビルドも始まります

### 受信箱・まとめて更新・分岐の一覧
- **📬 受信箱**（左のメニュー）：チームからの**招待**（参加する／お断りする）と、GitHub の**お知らせ**（変更の提案・課題・メンション・レビュー依頼など）をまとめて表示します。件数は左のメニューに印で出て、3分ごとに自動で確認します。「🔄 いま確認する」で**手動でも確認**でき、「ブラウザで開く」「既読にする」「すべて既読にする」ができます（GitHub 上でも既読になります）。
- **🔃 まとめて更新**（上部バー／メニュー「操作」→ Ctrl+Shift+R）：①サーバーの更新を確認 → ②新しいものがあれば取り込む → ③受信箱（招待・お知らせ）を確認、を1ボタンで順に行います。取り込みでぶつかりが出たら、そこで止めて解決へ案内します。
- **左のメニューの分岐の一覧**：「作業の分岐」の下に、手元の分岐（初期状態で開く）とサーバー上の分岐（初期状態で閉じる）を折りたたみ式で表示します。手元の分岐をクリックすると切り替わります。
- **右クリックから「管理しない一覧に追加」**：「まだ含めていない変更」のファイルを右クリックすると、「このファイルだけ／同じ種類すべて（*.log）／このフォルダごと」から選んで追加できます。（すでに記録済みのファイルは、追加しても管理が外れないため選べません）

### ログイン切れ・SSH鍵エラーの自動復旧
アップロード・取り込み・ダウンロードなどが**認証エラー**で失敗したら、エラーの箱で終わらず、その場で復旧へ案内します。

| 起きたこと | アプリの動き |
|---|---|
| GitHubのログインの期限切れ・トークンの取り消し | 「🔑 GitHubにログインし直してください」を表示 →「ログインし直す」でログイン画面へ → **ログインできたら、さっきの操作（アップロードなど）を自動でやり直す** |
| ログインは有効なのに認証が通らない（古い保存済みパスワードなど） | まず静かに、gitが使うログイン情報を設定し直して再試行。それでも通らなければ、ログインの入れ直しを案内 |
| ログインはできているが「workflow」の権限が足りない（`.github/workflows` のファイルを送るとき） | 「🔑 ログインの権限が足りません」を表示 →「ログインし直す」で、`repo, read:org, workflow` の権限つきでログインし直し → 操作を自動でやり直す。（ブラウザログインは、最初から workflow の権限つきで行います） |
| SSH鍵で入れない（鍵の期限切れ・未登録・変更など） | 接続先を「SSH形式 → HTTPS形式」に切り替える案内（変更内容を表示）→ 切り替えたら、操作を自動でやり直す |
| 操作していない間にログインが切れた | 10分ごと（とウィンドウに戻ったとき）に確認し、切れていたら同じ案内を表示。「あとで」を選ぶと1時間は出しません |

- 作業中のファイルや、まだ送っていない記録は消えません。やり直しは**1回だけ**で、それでも失敗したときは通常のエラーを表示します（案内をくり返しません）
- ネットワークが切れている・書き込み権限がない（403）・ぶつかり、などは「ログインし直しても直らない」ため、この案内の対象外です
- 「あとで」を選んだときは、エラーの箱を重ねません
- 見分けのルールは `src/auth-errors.js`、画面側の案内は `renderer/recovery.js` にまとまっています

### 自動更新（新しい版のお知らせ）
アプリを開いている間、GitHub の「Releases」に新しい版が出ていないかを自動で確認し（起動15秒後と、その後6時間ごと）、見つかったら**画面の上に帯でお知らせ**します。

| 環境 | 「更新する」を押すと |
|---|---|
| Windows のインストーラー版 / Linux の AppImage | アプリの中でダウンロード（進み具合を表示）→「🔄 再起動して更新」で入れ替わり、自動で開き直します |
| Mac・Windows のポータブル版・deb 版 | ダウンロードページをブラウザで開きます（入れ直してもらう形） |
| 開発中（`npm start`）・ローカルで作ったインストーラー | 更新の確認は行いません（「設定」画面に理由を表示） |

- 帯は「あとで」で閉じられます。閉じても、左のメニューの下の「🆕 新しい版があります」と、「設定」→「アプリの更新」からいつでも更新できます
- メニュー「ヘルプ → 新しい版を確認…」で、手動でも確認できます。「設定」で自動確認のオン／オフもできます
- **勝手に入れ替えることはありません**（ダウンロードは「更新する」を押したときだけ。ダウンロード済みの更新は、アプリを閉じるときにも入れ替わります）
- ダウンロードしたファイルは、更新の目録（`latest*.yml`）に書かれた sha512 の値と一致するか確認してから使います（ダウンロードの途中で壊れていないかの確認です。コード署名の代わりにはなりません）

**このソフトから新しい版を出す手順**
1. `package.json` と `package-lock.json` の版を同じ数字に更新します。
2. アプリの「変更」画面でそのファイルを記録し、「アップロード」します。
3. 「GitHub」→「リリース」→「リリースを作る」を開き、同じ数字の `v1.0.0` のようなバージョン名を入力して公開します。
4. タグがGitHubに送られると、GitHub Actions が3OS分のインストーラーと更新の目録を作ってリリースに追加します。使っている人のアプリが、新しい版を見つけます。

注意
- タグと `package.json` の版がちがうと、Actions が止まります（更新が見つからなくなるのを防ぐため）
- 自動更新の配布先は、GitHub Actions で作ったインストーラーにだけ埋め込まれます。`build-installer.bat` などで手元で作ったものは、更新の確認をしません
- **Mac は、コード署名をしていないと自動で入れ替えられない**ため、お知らせ＋ダウンロードページの案内になります。署名するようになったら、`main.js` の `macSigned: false` を `true` にし、`package.json` の `mac.target` に `zip` を足してください
- 配布ファイルの名前は、GitHub が日本語を取り除いてしまうため、半角英数字にしています（更新の目録とずれると、ダウンロードに失敗するため）

### アップロード前の安全チェック
「アップロード」を押すと、**これから送る記録だけ**（まだサーバーにない記録）を、このパソコンの中で調べます。外部に内容が送られることはありません。
- **秘密情報を含みやすいファイル名**：`.env`（`.env.example` などは除く）、秘密鍵（`id_rsa`・`*.pem`・`*.key`）、`credentials.json`、`.npmrc` など → 「要注意」
- **中身のパスワード・キー**：秘密鍵、AWS・GitHub・Slack・Google・Stripe のキー、`DB_PASSWORD = "..."` のような記述（画面には秘密の値そのものは出さず、ファイル名と行番号だけ表示）
- **大きなファイル**：50MB超は「念のため」、**100MB超はGitHubが拒否するため「送れません」**（「それでも送る」は出しません）
- 「やめる」が初期選択。直し方の手順と「🚫 管理しない一覧に追加」ボタンを表示します
- 強制アップロードにも同じ確認が入ります。「設定」画面でオフにもできます
- 検出ルールは `src/safety.js` にまとまっています（誤検出・見逃しがあれば、ここを調整します）

## 機能

- フォルダを開く / 新しく作る / ダウンロードして始める
- 変更一覧・差分表示・**かたまり単位の記録／破棄**・変更を記録・直前の記録の修正／取り消し
- 履歴（分岐図・検索・詳細・取り消しの記録・記録のコピー・巻き戻し・目印）
- 作業の分岐（作成・切替・合流・名前変更・削除・サーバー上の分岐・強制アップロード）
- ぶつかり（競合）の解決：自分の版／取り込む側の版／手で修正
- 一時退避、目印（タグ）、接続先（リモート）管理、管理しないファイル（.gitignore）
- GitHub：ログイン（ブラウザ／トークン）、リポジトリ一覧・公開、変更の提案（PR）、課題・相談（Issue）
- すべてのエラーを日本語に翻訳（元のメッセージは「くわしい内容」で確認可）
- ログイン切れ・SSH鍵エラーの自動復旧、アプリの自動更新のお知らせ
